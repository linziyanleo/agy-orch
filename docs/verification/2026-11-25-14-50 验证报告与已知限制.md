## 三、目前不能确认的部分与已知限制

- 入口覆盖边界：本机 `agy` CLI 入口已实测确认可发现 `~/.gemini/config/skills/agy-orch/SKILL.md`，但 Antigravity 桌面 App 图形界面的交互式触发与前端展示未在无头终端中单独做 UI 自动化验证，仍需在 App 对话界面中做一次人工抽检。
- 非 Codex 后端实测深度：`agy`、`qodercli`、`pi` 与 `claude-code` 已完成配置文件核对与本机二进制发现校验（其中 `claude` 在本机未安装，显示 `available: false`），但端到端真实模型运行仅在 `codex`（`gpt-6.2-sol`）上执行；`qodercli` 与 `pi` 的 `jsonl-generic` 解析器及无原生 `--output-schema` 时的 JSON 遵循率尚未做真实模型回归。
- 隔离 `--worktree` 生命周期：`delegate --worktree` 创建的分离 worktree 位于 `${AGY_ORCH_STATE_DIR:-~/.local/state/agy-orch}/worktrees/<run_id>`，为便于人工审查与合并不会在命令结束时自动删除，长期使用后需要人工或后续命令执行 `git worktree remove` 与 `git worktree prune` 清理。
- 触发评估集覆盖：`skills/agy-orch/evals/trigger-evals.json` 已提供 20 条应触发与不应触发查询，但尚未通过 `skill-creator` 的多轮在线触发基准脚本做真实模型触发率统计。
- 状态目录并发模型：当前单写者锁按 `effective_cwd` 隔离同一仓库并发 `delegate`，若不同终端直接手动编辑同一工作区文件而不经 `agy-orch`，运行时只能在结束或调用 `check-freshness` 时通过树指纹事后检测，无法阻止外部进程写盘。
